List, search and manage all job triggers.

Each row shows the Name, the Listening Event, the Schedule, the Destination Event, the Process Executor, the Updated at, plus the status flags Enabled.

The page is visible with the `access.system.job.triggers` grant.

## Pages routes

- `/system/job/triggers` — List, search and manage all job triggers. *(this page)*
- `/system/job/triggers/create` — Create a new job trigger.
- `/system/job/triggers/{uuid}` — View and edit an existing job trigger.

## What you can do here

### How to create a new job trigger
1. Click **New** in the toolbar.
2. Fill in the form — required: **Name**, **Destination Event**, **Process Executor**, **Enabled**.
3. Click **Save** — the new job trigger is created.

### How to edit a job trigger
1. Open the row actions menu on the job trigger and click **Edit**.
2. Update the fields — required: **Name**, **Destination Event**, **Process Executor**, **Enabled**.
3. Click **Save** — the changes to the job trigger are saved.

### How to delete a job trigger
1. Open the row actions menu on the job trigger and click **Delete**.
2. Confirm the deletion in the dialog — the job trigger is soft-deleted and can be restored.

### How to restore a deleted job trigger
1. Set the deleted-records filter to **Deleted only** or **All records** to show recoverable records.
2. Open the row actions menu on the job trigger and click **Restore**.
3. Confirm in the dialog — the job trigger is active again.

### How to view the change history of a job trigger
1. Open the row actions menu on the job trigger and click **Audit history**.
2. The version history of the job trigger will appear on the right sheet panel.

| **Filter** | no | yes | yes | JSON conditions that must all match the event payload for the trigger to fire — an array of `{ field, op, value }` entries evaluated against the event. |
| **Schedule** | yes | yes | yes | When the trigger fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you. |
| **Destination Event** | yes | yes | yes | What the trigger does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services. |
| **Payload mapping** | no | yes | yes | How to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a trigger context value (actor, trigger id, fire time). Leave empty to forward the event payload unchanged. |

## Actions

### Row actions

| Action | Status | Permission | What it does | Require Step-Up Auth |
|--------|--------|------------|--------------|----------------------|
| **create** | ENABLED | `_authenticated_admin` | Creates a new job trigger | no |
| **update** | ENABLED | `_authenticated_admin` | Opens the job trigger for editing | no |
| **delete** | ENABLED | `_authenticated_admin` | Marks the job trigger as deleted but keeps it so it can be restored | no |
| **restore** | ENABLED | `_authenticated_admin` | Brings a soft-deleted job trigger back | no |
| **purge** | DISABLED | — | Removes the job trigger forever | no |
| **audit history** | ENABLED | `_authenticated_admin` | Shows the change history of the job trigger | no |

- Creating a new job trigger is available on this page — the create action opens the create form in the same tab and it requires the `_authenticated_admin` permission.
- Editing a job trigger is available on this page — the row action opens the record in the same tab and it requires the `_authenticated_admin` permission.
- Soft-deleting a job trigger is available on this page — marks the job trigger as deleted but keeps it so it can be restored and it requires the `_authenticated_admin` permission.
- Restoring a soft-deleted job trigger is available on this page — brings a soft-deleted job trigger back and it requires the `_authenticated_admin` permission.
- Permanently deleting a job trigger is not available on this page — no permission is declared for it on job triggers.
- Viewing the change history of a job trigger is available on this page — every job trigger keeps a full version history and it requires the `_authenticated_admin` permission.
