List, search and manage all job rules.

Each row shows the Name, the Listening Event, the Schedule, the Destination Event, the Process Executor, the Updated at, plus the status flags Enabled.

The page is visible with the `access.system.job.rules` grant.

## Pages routes

- `/system/job/rules` — List, search and manage all job rules. *(this page)*
- `/system/job/rules/create` — Create a new job rule.
- `/system/job/rules/{uuid}` — View and edit an existing job rule.

## What you can do here

### How to create a new job rule
1. Click **New** in the toolbar.
2. Fill in the form — required: **Name**, **Listening Event**, **Destination Event**, **Schedule**, **Process Executor**, **Enabled**.
3. Click **Save** — the new job rule is created.

### How to edit a job rule
1. Open the row actions menu on the job rule and click **Edit**.
2. Update the fields — required: **Name**, **Listening Event**, **Destination Event**, **Schedule**, **Process Executor**, **Enabled**.
3. Click **Save** — the changes to the job rule are saved.

### How to delete a job rule
1. Open the row actions menu on the job rule and click **Delete**.
2. Confirm the deletion in the dialog — the job rule is soft-deleted and can be restored.

### How to restore a deleted job rule
1. Set the deleted-records filter to **Deleted only** or **All records** to show recoverable records.
2. Open the row actions menu on the job rule and click **Restore**.
3. Confirm in the dialog — the job rule is active again.

### How to view the change history of a job rule
1. Open the row actions menu on the job rule and click **Audit history**.
2. The version history of the job rule will appear on the right sheet panel.

## Columns

| **Name** | yes | yes | yes |  |
| **Listening Event** | yes | yes | yes | The event that can trigger this rule: when something happens in the system (e.g. a customer crosses a threshold) the rule can run. Pick an available event or type an event name. |
| **Filter** | no | yes | yes | JSON conditions that must all match the event payload for the rule to fire — an array of `{ field, op, value }` entries evaluated against the event. |
| **Schedule** | yes | yes | yes | When the rule fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you. |
| **Destination Event** | yes | yes | yes | What the rule does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services. |
| **Payload mapping** | no | yes | yes | How to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a rule context value (actor, rule id, fire time). Leave empty to forward the event payload unchanged. |
| **Process Executor** | yes | yes | yes | `user` runs the action as the triggering user (with their permissions); `system` runs with module privileges. Must match the lane in the destination subject. |
| **Enabled** | yes | yes | yes | When on, the rule reacts to the event you chose. Turn it off to pause the rule without deleting it. |

## Actions

### Row actions

| Action | Status | Permission | What it does | Require Step-Up Auth |
|--------|--------|------------|--------------|----------------------|
| **create** | ENABLED | `_authenticated_admin` | Creates a new job rule | no |
| **update** | ENABLED | `_authenticated_admin` | Opens the job rule for editing | no |
| **delete** | ENABLED | `_authenticated_admin` | Marks the job rule as deleted but keeps it so it can be restored | no |
| **restore** | ENABLED | `_authenticated_admin` | Brings a soft-deleted job rule back | no |
| **purge** | DISABLED | — | Removes the job rule forever | no |
| **audit history** | ENABLED | `_authenticated_admin` | Shows the change history of the job rule | no |

- Creating a new job rule is available on this page — the create action opens the create form in the same tab and it requires the `_authenticated_admin` permission.
- Editing a job rule is available on this page — the row action opens the record in the same tab and it requires the `_authenticated_admin` permission.
- Soft-deleting a job rule is available on this page — marks the job rule as deleted but keeps it so it can be restored and it requires the `_authenticated_admin` permission.
- Restoring a soft-deleted job rule is available on this page — brings a soft-deleted job rule back and it requires the `_authenticated_admin` permission.
- Permanently deleting a job rule is not available on this page — no permission is declared for it on job rules.
- Viewing the change history of a job rule is available on this page — every job rule keeps a full version history and it requires the `_authenticated_admin` permission.
