Create a new job trigger.

The page is visible with the `access.system.job.triggers.create` grant.

## Pages routes

- `/system/job/triggers` — List, search and manage all job triggers.
- `/system/job/triggers/create` — Create a new job trigger. *(this page)*
- `/system/job/triggers/{uuid}` — View and edit an existing job trigger.

## What you can do here

### How to create a new job trigger
1. On the **Triggers** list page, click **New** in the toolbar.
2. Fill in the fields below — required: **Name**, **Destination Event**, **Run As**.
3. Click **Save** — the new job trigger is created.

## Fields

| Field | Required | Notes |
|-------|----------|-------|
| **Name** | required | max 200; min 5 |
| **Listening Event** | optional | The event that can trigger this trigger: when something happens in the system (e.g. a customer crosses a threshold) the trigger can run. Pick an available event from the list; offers the event subjects published by the registered modules (48 declared); only declared values can be selected |
| **Destination Event** | required | What the trigger does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services; offers the callable work subjects declared by the registered modules (3 declared); only declared values can be selected |
| **Run As** | required | `originator` runs the action as the user who triggered the event, with their permissions — requires an event source; `author` runs as the trigger's author, identity resolved fresh at dispatch time; `system` runs with module privileges; max 20 |
| **Schedule** | optional | When the trigger fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you |
| **Filter** | optional | Restrict which events fire this trigger — the job runs only when every added condition matches the event's data. Leave empty to react to every event; edited as structured JSON with schema assistance |
| **Payload mapping** | optional | interactive payload-map builder — How to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a trigger context value (actor, trigger id, fire time). Leave empty to forward the event payload unchanged |

- The **Name** field is a required field that allows up to 200 characters and requires at least 5 characters.
- The **Listening Event** field is an optional field — the event that can trigger this trigger: when something happens in the system (e.g. a customer crosses a threshold) the trigger can run. Pick an available event from the list; offers the event subjects published by the registered modules (48 declared); only declared values can be selected.
- The **Destination Event** field is a required field — what the trigger does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services; offers the callable work subjects declared by the registered modules (3 declared); only declared values can be selected.
- The **Run As** field is a required field that allows up to 20 characters — `originator` runs the action as the user who triggered the event, with their permissions — requires an event source; `author` runs as the trigger's author, identity resolved fresh at dispatch time; `system` runs with module privileges.
- The **Schedule** field is an optional field — when the trigger fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you.
- The **Filter** field is an optional field — restrict which events fire this trigger — the job runs only when every added condition matches the event's data. Leave empty to react to every event; edited as structured JSON with schema assistance.
- The **Payload mapping** field is an optional interactive payload-map builder — how to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a trigger context value (actor, trigger id, fire time). Leave empty to forward the event payload unchanged.
