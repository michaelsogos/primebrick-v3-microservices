Create a new job trigger.

The page is visible with the `access.system.job.triggers.create` grant.

## Pages routes

- `/system/job/triggers` — List, search and manage all job triggers.
- `/system/job/triggers/create` — Create a new job trigger. *(this page)*
- `/system/job/triggers/{uuid}` — View and edit an existing job trigger.

## What you can do here

### How to create a new job trigger
1. On the **Triggers** list page, click **New** in the toolbar.
2. Fill in the fields below — required: **Name**, **Destination Event**, **Run As**.
3. Click **Save** — the new job trigger is created.

## Fields

| Field | Required | Notes |
|-------|----------|-------|
| **Name** | required | max 200 |
| **Listening Event** | optional | The event that can trigger this trigger: when something happens in the system (e.g. a customer crosses a threshold) the trigger can run. Pick an available event from the list; offers the event subjects published by the registered modules (26 declared); only declared values can be selected |
| **Destination Event** | required | What the trigger does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services; offers the callable work subjects declared by the registered modules (5 declared); only declared values can be selected |
| **Run As** | required | `originator` runs the action as the user who triggered the event, with their permissions — requires an event source; `author` runs as the trigger's author, identity resolved fresh at dispatch time; `system` runs with module privileges; max 20 |
| **Schedule** | optional | When the trigger fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you |
| **Filter** | optional | JSON conditions that must all match the event payload for the trigger to fire — an array of `{ field, op, value }` entries evaluated against the event; edited as structured JSON with schema assistance |
| **Payload mapping** | optional | interactive payload-map builder — How to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a trigger context value (actor, trigger id, fire time). Leave empty to forward the event payload unchanged |

- The **Name** field is a required field that allows up to 200 characters.
- The **Listening Event** field is an optional field — the event that can trigger this trigger: when something happens in the system (e.g. a customer crosses a threshold) the trigger can run. Pick an available event from the list; offers the event subjects published by the registered modules (26 declared); only declared values can be selected.
- The **Destination Event** field is a required field — what the trigger does when it triggers: the operation to run (e.g. send an email). Available destinations depend on the active services; offers the callable work subjects declared by the registered modules (5 declared); only declared values can be selected.
- The **Run As** field is a required field that allows up to 20 characters — `originator` runs the action as the user who triggered the event, with their permissions — requires an event source; `author` runs as the trigger's author, identity resolved fresh at dispatch time; `system` runs with module privileges.
- The **Schedule** field is an optional field — when the trigger fires — `@every <n><unit>` for intervals, `@at <timestamp>` for one-shot, or a 5-field cron expression. The assistant button builds one for you.
- The **Filter** field is an optional field — JSON conditions that must all match the event payload for the trigger to fire — an array of `{ field, op, value }` entries evaluated against the event; edited as structured JSON with schema assistance.
- The **Payload mapping** field is an optional interactive payload-map builder — how to build the request payload for the destination — per destination field, pick a constant value, a path into the event payload, or a trigger context value (actor, trigger id, fire time). Leave empty to forward the event payload unchanged.

The **Listening Event** field offers these declared published event subjects:

- `events.crm.customer.>`
- `events.crm.customer_type.>`
- `events.crm.company_dimension.>`
- `events.crm.legal_form.>`
- `events.crm.local_address_type.>`
- `events.crm.qualification.>`
- `events.crm.marketing_qualification.>`
- `events.crm.contact_type.>`
- `events.crm.account_kind.>`
- `events.crm.customer_link_type.>`
- `events.crm.consent_type.>`
- `events.crm.local_address.>`
- `events.crm.customer_account.>`
- `events.crm.customer_contact.>`
- `events.crm.customer_link.>`
- `events.crm.customer_consent.>`
- `crm.customer_changed` — **Customer changed** — Fires when a customer row is created, updated or deleted — carries the row snapshot plus change metadata
- `crm.customer_high_value` — **High-value customer** — Semantic event — sales logic decided this customer crossed the high-value threshold. Carries the customer, the account manager and the trigger details
- `crm.customer_payout` — **Customer payout** — Fires when a payout is recorded for a customer — carries the customer, the account manager and the payout details
- `webhook.*.received`
- `jobs.result.ai.*`
- `events.job.job_trigger.>`
- `events.job.job_schedule.>`
- `events.job.job_run.>`
- `jobs.ctl.triggers.changed` — **Triggers changed** — Fired when the job trigger set changes — `jobs` domain, `ctl` control channel, `triggers` resource, `changed` verb. The triggers engine re-arms schedules on it
- `emailsender.response.*`

The **Destination Event** field offers these declared callable work subjects:

- `crm.emit_fake_event` — **Emit fake event (PoC)** — Dev/PoC harness — publishes a canned or overridden fake payload on one of the declared crm.* event subjects
- `crm.partition_maintenance` — **Partition maintenance** — Drops expired audit and entity partitions and sweeps rows past their declared retention. Takes no parameters
- `ai.partition_maintenance` — **Partition maintenance** — Drops partitions whose retention window has elapsed, on every entity that declares one. Takes no parameters
- `job.partition_maintenance` — **Partition maintenance** — Drops expired audit and entity partitions and sweeps rows past their declared retention. Takes no parameters
- `emailsender.send` — **Send email** — Sends a templated email through the configured provider — accepts template code, recipients and merge variables
