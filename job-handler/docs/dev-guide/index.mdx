# JobHandler (`primebrick-job`)

JobHandler is the **scheduler, governance, and observability** service for the
Primebrick job fabric. It never executes domain work — every job's executor
lives in the owning domain service.

## Architecture

```
Service boot                primebrick-job                 JetStream           owning service
────────────                ──────────────                 ─────────           ──────────────
entity registry has
@PartitionField? ──declare──▶ jobs.ctl.schedule.request ──▶ jobs.schedule.<svc>.<name>
                            (L1+L2 shield, namespace check)      │ (NATS native scheduler)
                                                                 ▼
                                                    jobs.due.<lane>.<svc>.<action>
                                                                 │
                            ◀── jobs.result.<svc>.<name> ◀── durable consumer ──▶ executor
                            │                                                    (DAL/service logic)
                            ▼
                      job.job_runs (status, duration, error, report)
```

- **Scheduler** = the NATS server (`allow_msg_schedules` on the `JOBS` stream).
- **Sole writer of `jobs.schedule.*`** = job-handler via `jobs.ctl.schedule.request`.
  Arm/disarm is an **atomic protocol**, awaited end-to-end by `callNats`:
  declare → PubAck → read-back verify → mirror upsert (a mirror failure
  compensates with a purge); disarm verifies the declaration is *absent*
  before flipping the mirror. Re-arming an already-fired/expired `@at`
  for the same spec is a successful no-op — the reply is
  `{ armed: false, skipped: "terminal-once" }` (a past `@at` would fire
  immediately on re-declare).
- **Executor** = a durable JetStream consumer inside the domain service.
- **Triggers** = `job.job_triggers` domain data (NOT config) — the triggers engine
  dispatches them: event+schedule gate, event-only immediate, schedule-only timer.
- **Infrastructure jobs** = metadata-derived (`@PartitionField` on an entity →
  the owning service self-declares its own schedule at boot).

## Subjects

| Subject | Purpose |
|---------|---------|
| `jobs.schedule.<owner>.<name>` | Schedule declaration (stored, last-msg-wins) |
| `jobs.due.user.<svc>.<action>[.<id>]` | Due message — user lane (auth propagates) |
| `jobs.due.system.<svc>.<action>[.<id>]` | Due message — system lane |
| `jobs.result.<svc>.<name>` | Execution report → recorded in `job.job_runs` |
| `jobs.cancel.*` | Schedule cancellation |
| `jobs.ctl.schedule.request` / `jobs.ctl.schedule.cancel` | Governed control routes |

## Namespace security

A remote caller may only declare inside its own `jobs.schedule.<svc>.*`
namespace **and** the due target must land back on its own service
(`jobs.due.<lane>.<same-svc>.*`). Internal callers (triggers engine, admin HTTP
action) own the `job` namespace and may target any service — that's the point
of admin-managed schedules.

## Domain data (schema `job`)

- `job_triggers` — business triggers: `event_subject` and/or `schedule_spec`
  (at least one) → `target_subject`; `execution_context`: `user`|`me`|`system`.
- `job_schedules` — **read-only mirror** of NATS declarations (`kind`: `infra_derived` | `trigger` (`manual` absorbed into schedule-only triggers),
  `schedule_type`: `recurring` | `once`, `status`: `armed` | `disarmed` | `fired` | `expired`).
- `job_runs` — execution history: `status` (`dispatched` | `succeeded` | `failed` | `lost`),
  `duration_ms`, `fire_seq`, error fields, report (jsonb). The SDK transport
  middleware publishes `jobs.result.<svc>.<name>` for every correlated
  handler (`x-job-run-id` / `x-job-schedule-subject` headers); a `dispatched`
  run that never gets a result is flipped to `lost` by the sweeper.
- `config_entries` — mandatory per-service config (cadence, ports, shield refs).

## HTTP surface (via BE `/svc/job/*` proxy)

| Route | Description |
|-------|-------------|
| `GET /api/v1/entities/job_trigger|job_schedule|job_run/…` | Canonical entity CRUD (meta/list/get/…) |
| `POST /api/v1/actions/disarm-job` | Disarm a schedule (admin) |
| `POST /api/v1/actions/job-run-stats` | Per-schedule execution buckets for sparklines — adaptive `bucket_unit` (hour/day/week/month chosen so the span lands in ~8–30 buckets) |

## Partition maintenance (first real consumer)

`@PartitionField` on an entity marks it partitioned; `@PartitionChildOf` marks
the logical children purged leaf→root before each partition drop. The owning
service calls `dal.partitionMaintenance(ENTITY_REGISTRY)` from its executor —
job-handler only sees subjects, never tables.

Config: `partition_maintenance_schedule` in the service's `config_entries`
(default `@daily`).

## Fire-time auth freshness

Every scheduled/immediate user-lane dispatch crosses the due-forwarder
(`jobs.due.user.job.forward.>`), which runs a mechanical auth checkpoint
before republishing: the actor's resolved AuthUser is cached under
`auth:snap:<uuid>` and reused only while it postdates the BE-stamped
epochs (`auth:epoch` global on role writes, `auth:user_epoch:<uuid>` on
user writes). Miss/expired/epoch-stale → re-resolve via
`auth.ctl.resolve_user`; `null` (deleted/disabled actor) → the fire is
refused and the run recorded `failed`; an unreachable backend falls back
to the due message's own headers with a warn. System lane bypasses it.

## Admin UI

The job module owns its UI via `JOB_NAV` (`src/nav-declaration.ts` →
`service_registry.endpoints.nav`, `route_prefixes: ["/system/job"]`,
access namespace `access.system.job`).

- **List pages** (`kind: "list"`) — schedules / runs / triggers lists are
  host-rendered entity-table archetypes with per-row Kestra-style
  stacked-bar execution sparklines.
- **Trigger create/detail** (`kind: "create"/"detail"` + `page_props.form`)
  — the host entity-form archetype renders them; the mutually-mandatory
  source/schedule pair and the lane policy ride the closed-vocab
  `job_trigger_shape` validator.
- **Remote sheet** (`nav.sheets[]`) — `job.runDetail` mounts the run
  drill-down panel from the same chunk via the host sheet engine.
- **Serving**: `GET /api/v1/module-assets/*` streams `fe/dist` (vite build
  under `fe/`); the gateway path is
  `/svc/job/api/v1/module-assets/jobs-page.js`.
